# BAET Architecture Simplification Plan

## Executive Summary

This plan outlines a systematic approach to simplify the BAET (Binance Adaptive Ensemble Trader) codebase architecture. The current codebase contains ~60 Python modules across 12 packages, resulting in unnecessary complexity for maintenance and onboarding. The goal is to reduce this to ~20 modules while preserving all functionality.

---

## Phase 1: Cleanup and Removal (Week 1)

### Milestones
- Delete all excluded files from pyproject.toml (8 files)
- Remove unused dashboard components (control.py, app_old.py)
- Reduce module count by 20% (from 60 to ~48)

### Resource Allocation
- **Human Resources**: 1 developer (2 days)
- **Technical Resources**: Git version control, IDE with refactoring tools
- **Financial**: Minimal (existing development time)

|------|----------|--------------|
| Remove excluded files from ruff config | 0.5 day | None |

## Risk Mitigation

1. **Breaking Changes**: All changes maintain backward compatibility through careful API preservation
2. **Testing Gaps**: Each phase includes comprehensive testing before proceeding
3. **Merge Conflicts**: Work in feature branches with regular rebasing
4. **Data Loss**: All work committed frequently with descriptive messages

---

## Success Metrics

- Module count reduced from ~60 to ~20 (66% reduction)
- All existing tests passing
- Single entry point for each domain (risk, paper, dashboard, data)
- Improved code navigability (measured by file open operations during development)
- Faster onboarding time for new developers

---

## Rollback Plan

If issues arise, each phase is independently revertible through git. The consolidation is designed so that if any phase fails, previous phases remain functional.
