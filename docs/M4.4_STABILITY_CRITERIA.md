# M4.4: Stability Criteria for Paper Trading

## Objective
Define clear, measurable criteria to determine when paper trading is "stable" and ready for live deployment.

## Observation Window
**Minimum: 7 days continuous operation**
**Recommended: 14 days for higher confidence**

## Stability Metrics

### 1. Uptime Requirements

| Metric | Target | Measurement |
|--------|--------|--------------|
| Total Uptime | > 99% | (Total runtime - downtime) / Total runtime |
| Max Single Downtime | < 5 minutes | Longest continuous period offline |
| Restart Count | < 5 per week | Number of unplanned restarts |
| Automatic Recovery | 100% | Percentage of crashes that auto-restart successfully |

**Measurement Method:**
```bash
# Check process uptime
psutil.Process(pid).create_time()

# Count restarts in logs
grep "Paper trading engine started" logs/paper/*.log | wc -l
```

### 2. Performance Requirements

| Metric | Target | Notes |
|--------|--------|-------|
| Memory Usage | Stable (±10%) | No continuous growth over 24 hours |
| CPU Usage | < 50% average | On target hardware (2 vCPU, 4GB RAM) |
| Log File Size | < 100MB/day | Monitor disk space usage |
| API Rate Limits | < 80% of limit | Avoid Binance rate limiting |

**Memory Leak Test:**
```python
# Take memory snapshots every hour
import psutil
process = psutil.Process()
memory_mb = process.memory_info().rss / 1024 / 1024
# Plot over 24 hours - should be flat, not trending up
```

### 3. Data Integrity Requirements

| Check | Criteria | Validation Method |
|-------|-----------|-------------------|
| Portfolio Consistency | balance + unrealized_pnl = equity | Check each PORTFOLIO_UPDATE |
| Trade Completeness | Every ORDER_FILLED has matching TRADE | Cross-reference logs |
| Log Validity | 100% valid JSON lines | `jq . < logfile` or custom parser |
| Equity Curve Continuity | No gaps > 5 minutes | Check timestamps in sequence |
| Position Accuracy | Positions match trade history | Replay trades, verify final state |

**Validation Script:**
```bash
python -c "
from baet.dashboard.data_loader import parse_log_file
entries = parse_log_file('logs/paper/latest.log')
# Check for gaps
timestamps = [e['timestamp'] for e in entries if 'timestamp' in e]
# Analyze...
"
```

### 4. Error Handling Requirements

| Error Type | Handling | Acceptance |
|------------|-----------|-------------|
| Network Errors (Binance API) | Retry with backoff | Logged, doesn't crash |
| Data Errors (malformed candles) | Skip candle, continue | Logged with context |
| Calculation Errors (NaN, Inf) | Use defaults, continue | Logged with values |
| Unhandled Exceptions | Catch, log, restart | < 1 per day |

**Error Rate Targets:**
- WARNING level: < 10 per day
- ERROR level: < 3 per day
- CRITICAL: 0 (if any, must be investigated)

### 5. Trading Logic Requirements

| Check | Criteria | 
|-------|-----------|
| Signal Generation | Continuous (no gaps > 1 hour during market hours) |
| Risk Checks | Every trade gated by RiskEngine |
| Order Simulation | All orders simulated with slippage/fees |
| Portfolio Updates | After every trade |
| Regime Detection | Running and updating |

## Monitoring Dashboard

Use the Streamlit dashboard (`python scripts/run_dashboard.py`) to monitor:

1. **Overview Tab**
   - Equity curve should be continuous
   - No flatlines > 1 hour (indicates stalled engine)

2. **Positions Tab**
   - Positions should be reasonable sizes
   - No orphaned positions (should close eventually)

3. **Trades Tab**
   - New trades appearing regularly
   - P&L should be realistic (not all wins or all losses)

4. **Logs Tab**
   - Filter by ERROR/WARNING
   - Check frequency of issues

## Acceptance Criteria

M4.4 is **COMPLETE** only when ALL of the following are true:

- [ ] Paper trading runs continuously for 7-14 days
- [ ] Uptime > 99% over observation period
- [ ] No unhandled crashes (all exceptions caught and logged)
- [ ] Memory usage stable (no growth trend over 24 hours)
- [ ] All trades properly logged and visible in dashboard
- [ ] Portfolio state consistent in all log entries
- [ ] Log files are valid JSON (100% parseable)
- [ ] Dashboard accessible throughout observation period
- [ ] Observation log completed with daily entries
- [ ] Error rate within acceptable limits (< 3 ERROR per day)

## Validation Checklist

Run this checklist at the end of the observation period:

```bash
# 1. Check uptime
echo "Checking process logs for uptime..."
grep "started\|stopped\|crashed" logs/paper/*.log | head -20

# 2. Validate all log files
echo "Validating log files..."
for f in logs/paper/*.log; do
    python -c "
import json
with open('$f') as fp:
    for i, line in enumerate(fp):
        try:
            json.loads(line)
        except:
            print(f'Invalid JSON at line {i} in $f')
            exit(1)
print('OK: $f')
"
done

# 3. Check data integrity
python scripts/analyze_paper_logs.py logs/paper/paper_trading_*.log

# 4. Review error counts
echo "Error summary:"
grep -c "ERROR" logs/paper/*.log
grep -c "CRITICAL" logs/paper/*.log

# 5. Memory check (if monitoring data available)
# Plot memory usage over time
```

## Decision Point

After observation period:

**If ALL criteria met:** Mark M4.4 complete, proceed to M5.1a (Live Readiness)

**If SOME criteria not met:** 
- Document issues in observation log
- Fix root causes
- Extend observation period by 7 days
- Re-validate

**If CRITICAL issues found:**
- Stop observation
- Fix issues
- Re-implement M4.2a/M4.3a if needed
- Restart observation from scratch
